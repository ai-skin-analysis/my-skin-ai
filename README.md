# Smart Skin AI

## เริ่มใช้งาน

```powershell
.\.venv\Scripts\python.exe app.py
```

เปิด `http://127.0.0.1:5000` ในเบราว์เซอร์

## สร้างบัญชีแอดมิน

บัญชี bootstrap เดิมถูกปิดแล้ว ให้สร้างหรือรีเซ็ตแอดมินด้วยคำสั่งนี้ ระบบจะถามรหัสผ่านแบบซ่อนข้อความ:

```powershell
.\.venv\Scripts\python.exe manage.py create-admin --email admin@example.com
```

สำหรับ production ให้สร้างผ่าน console ที่ควบคุมและยืนยัน MFA ในครั้งเดียว
(ห้ามใส่รหัสแอดมินไว้ใน environment ของ service):

```powershell
.\.venv\Scripts\python.exe manage.py create-admin --email admin@example.com --enroll-mfa
```

## การตั้งค่าก่อนนำขึ้นใช้งานจริง

- สร้าง `FLASK_SECRET_KEY` ที่ยาวและสุ่ม แล้วกำหนดเป็น environment variable
- ตั้ง `FLASK_HTTPS=1` เมื่อเว็บไซต์ให้บริการผ่าน HTTPS
- ใช้ WSGI server ที่เหมาะสมแทน Flask development server
- เก็บ `private_uploads` และ `users.db` ในพื้นที่ที่เข้ารหัสและมีนโยบายสำรองข้อมูล/เก็บรักษาข้อมูลชัดเจน
- ตั้ง `SMART_SKIN_DATABASE` เป็นพาธของฐานข้อมูลที่แยกจากไฟล์โปรเจกต์ได้เมื่อ deploy และอย่าเก็บค่าลับใน Git
- ผู้ใช้ใหม่ต้องตั้งรหัสผ่านอย่างน้อย 12 ตัวอักษร โดยมีทั้งตัวอักษรและตัวเลข ระบบจำกัดความพยายามเข้าสู่ระบบจาก IP เดียวกันไว้ 5 ครั้งต่อ 15 นาที
- กำหนด `SMART_SKIN_PUBLIC_BASE_URL` และ SMTP ใน secret store เพื่อเปิดการตั้งรหัสผ่านใหม่แบบลิงก์ใช้ครั้งเดียว ระบบจะหมดอายุลิงก์ใน 30 นาที ใช้ซ้ำไม่ได้ และตัดเซสชันเดิมของบัญชีนั้นทั้งหมด
- ผู้ดูแลไม่สามารถอ่านหรือแสดงรหัสผ่านของผู้ใช้ได้ แต่ส่งลิงก์ตั้งรหัสผ่านใหม่แบบใช้ครั้งเดียวจากหน้า User Management ได้เมื่อกำหนด SMTP แล้ว
- ผู้ดูแลสามารถเปิด TOTP MFA จากหน้าแดชบอร์ดได้หลังตั้ง `SMART_SKIN_MFA_ENCRYPTION_KEY` ใน secret manager; คีย์นี้เข้ารหัส seed ของ Authenticator ในฐานข้อมูล และต้องต่างจาก `FLASK_SECRET_KEY` ใน production
- โหมด `SMART_SKIN_PUBLIC_INFORMATION_MODE=1` ปิดการสมัคร, login, บัญชี, รับภาพ และวิเคราะห์ภาพทั้งหมด เหลือเฉพาะข้อมูลสาธารณะ, privacy/terms, health check และข้อมูลอากาศที่ผู้ใช้ยินยอม
- ใน production ผู้สมัครใหม่ต้องยืนยันอีเมลด้วยลิงก์ใช้ครั้งเดียวก่อน แล้วจึงรอผู้ดูแลอนุมัติบัญชี; บัญชีที่มีอยู่ก่อนอัปเกรดจะไม่ถูกล็อกโดยอัตโนมัติ

โมเดลในโปรเจกต์เป็นเครื่องมือคัดกรองจากภาพ ไม่ใช่เครื่องมือวินิจฉัยโรค และต้องผ่านการตรวจสอบทางคลินิกก่อนนำไปใช้กับผู้ป่วยจริง

สำหรับ production ที่มีข้อมูลสุขภาพ ให้ทำตาม [PRODUCTION_DEPLOYMENT.md](PRODUCTION_DEPLOYMENT.md) ทั้งหมดก่อนตั้ง `SMART_SKIN_ENV=production` ระบบจะบล็อกการอัปโหลดภาพโดยอัตโนมัติจนกว่า metadata ของโมเดลจะมีผลประเมินอิสระ การปรับเทียบ และการอนุมัติ intended use ครบถ้วน

สำหรับการเปิดเว็บไซต์ผ่านอินเทอร์เน็ต ให้ทำตาม [PUBLIC_RELEASE_RUNBOOK.md](PUBLIC_RELEASE_RUNBOOK.md) ด้วย: ใช้ HTTPS, reverse proxy/WAF และ Waitress; ห้ามเปิด Flask development server หรือพอร์ต WSGI ตรงสู่สาธารณะ

สำหรับการเผยแพร่ **public-information mode** บน Google Cloud Run ให้ทำตาม
[deploy/gcp/README.md](deploy/gcp/README.md) ก่อน ระบบจะยังไม่รับบัญชีหรือภาพ
จนกว่าจะย้าย storage ออกจาก SQLite/ไฟล์ในเครื่องและผ่านเงื่อนไขการเปิดใช้โมเดลครบถ้วน

## ขยายเป็นหลายกลุ่มโรค

ระบบมี catalog เป้าหมาย 50 กลุ่มและ pipeline สำหรับฝึกโมเดลใหม่ แต่โมเดลที่แนบมาในปัจจุบันยังรองรับเพียง 6 กลุ่มเท่านั้น เพื่อไม่ให้แสดงผลเกินความสามารถของโมเดล อ่านขั้นตอนข้อมูล การฝึก และการประเมินได้ที่ [MULTICLASS_TRAINING.md](MULTICLASS_TRAINING.md) และดู release contract สำหรับเปิดใช้ครบ 50 กลุ่มที่ [MODEL_50_CLASS_RELEASE.md](MODEL_50_CLASS_RELEASE.md)

ผู้ดูแลสามารถเริ่มงานฝึก candidate model จากหน้า Admin ได้หลังชุดข้อมูลผ่าน preflight ระบบเก็บผล validation accuracy และ recall รายคลาสเพื่อใช้พัฒนาเท่านั้น งานดังกล่าวจะไม่เปิดใช้โมเดลกับผู้ใช้จริงโดยอัตโนมัติ

ผู้ใช้ทั่วไปสามารถเลือกใช้เรดาร์พื้นที่ใกล้เคียงได้เอง ระบบขอความยินยอมก่อนรับพิกัด, จัดเก็บเพียงตำแหน่งโดยประมาณและข้อมูลอากาศล่าสุดชั่วคราว และแสดงให้ผู้ดูแลที่ได้รับสิทธิ์เท่านั้น โดยไม่ระบุความเสี่ยงโรคจากตำแหน่ง
